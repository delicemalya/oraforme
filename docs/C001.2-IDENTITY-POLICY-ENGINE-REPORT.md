## 1. Architecture

### Principe directeur

Le Policy Engine est **pur** : il ne contient aucune logique d'authentification. Il reçoit un contexte pré-construit (`PolicyContext`) et rend des décisions (`PolicyDecision`). Toute action est traçable. Aucun blocage n'est silencieux.

### Flux de traitement

```
Auth Event (LOGIN_SUCCESS, LOGIN_FAILED, TOKEN_REFRESH, ...)
    │
    ▼
PolicyContext (données pré-fetched, jamais fetchées dans le moteur)
    │
    ▼
PolicyEvaluationEngine.evaluate(ctx)
    │  — sélectionne les politiques pour l'événement
    │  — vérifie les exceptions
    │  — appelle condition(ctx) (pure function, aucun DB call)
    │  — construit PolicyDecision (reason + evidence obligatoires)
    ▼
[PolicyDecision[]]
    │
    ├──► PolicyActionEngine.execute(decision)
    │         — dispatch par action type
    │         — fire-and-forget (action failure ≠ crash)
    │
    └──► writePolicyDecision(decision)
              — history.ts → policy_history (immuable)
              — policy_violations si DENY ou FLAG
```

|--------|---------|------|

## 2. Contrats

### PolicyContext

```typescript
interface PolicyContext {
  event:            PolicyEvent           // événement déclencheur (IP, device, provider…)
  recentHistory:    PolicyContextHistory  // données pré-fetched (jamais fetched dans le moteur)
  tenantConfig:     PolicyTenantConfig    // config tenant (sessions, MFA, expiration…)
  sessionStartedAt: string | null         // timestamp de début de session
}
```

**LOI : Le moteur ne fait aucun appel DB.** Toutes les données sont dans `ctx`.

### PolicyDecision

```typescript
interface PolicyDecision {
  policyId:    PolicyId
  policyName:  string
  verdict:     'ALLOW' | 'DENY' | 'FLAG' | 'MONITOR'
  severity:    'LOW' | 'MEDIUM' | 'HIGH' | 'CRITICAL'
  reason:      string      // TOUJOURS non vide — explication pour l'utilisateur
  action:      PolicyAction
  evidence:    PolicyEvidence  // données ayant déclenché la politique
  triggeredAt: string          // ISO timestamp
}
```

**LOI : `reason` est toujours non vide.** Aucune décision ne peut être sans explication.

## 4. Infrastructure de données

### Table `policy_history`

- Journal **immuable** (INSERT uniquement via service role)
- RLS : UPDATE/DELETE bloqués par policy ; SELECT limité au tenant
- 6 index (tenant+created_at, user+created_at, policy+created_at, verdict, severity, request_id)
- Archivage automatique : `fn_policy_history_cleanup(90)` — ALLOW/MONITOR uniquement

### Table `policy_violations`

- Sous-ensemble : seulement DENY et FLAG
- Champ `resolved` pour le suivi opérationnel
- Lié à `policy_history` par FK (CASCADE DELETE)

### Vue `policy_metrics_last_24h`

- Agrégats temps réel par tenant / policy / verdict / severity
- Utilisée par le dashboard sans charge sur la table principale

## 7. Lois Fondamentales respectées

| Loi | Application |
|-----|-------------|
| LOI-A (Single Source of Truth) | PolicyDecision = unique décision par (policyId, requestId) |
