## 2. Architecture d'intégration

### Pipeline complet (implémenté)

```
Auth Event (LOGIN_SUCCESS, LOGIN_FAILED, TOKEN_REFRESH, LOGOUT)
    │
    ▼
1. buildPolicyEvent()  ← construit PolicyEvent depuis les données de la requête
    │
    ▼
2. buildPolicyContext(event, tenantId, sessionStartedAt?)
    │  ─ Query 1 : fn_policy_context_counters(userId) — 1 requête agrégée
    │  ─ Query 2 : COUNT auth_logs WHERE LOGIN_FAILED AND ip (brute force IP)
    │  ─ Query 3 : SELECT ip, device, browser FROM auth_logs (login history)
    │  ─ fetchTenantConfig(tenantId) → DEFAULT_TENANT_CONFIG (C-003 ready)
    │
    ▼
3. evaluatePolicies(ctx, { stopOnFirstDeny: true })
    │  ─ filtre par triggerEvents
    │  ─ conditions pures (aucun DB call)
    │  ─ exception bypass si applicable
    │
    ▼
4. PolicyDecision[] → denyDecision?
    │
    ├─ DENY → executeAction() + writePolicyDecision() [fire-and-forget]
    │          → sign out + redirect /login?error=policy_denied&reason=...
    │
    └─ ALLOW/FLAG/MONITOR → logAuthEvent() + proceed
                             (FLAG/MONITOR: action + history fire-and-forget)
```

## 3. Détail des intégrations

### 3.1 Login Email/Password (`app/login/page.tsx`)

```typescript
// Après signInWithPassword succès
const verdict = await evaluateAuthClient('LOGIN_SUCCESS', { provider: 'email', durationMs })
if (verdict.denied) {
  await supabase.auth.signOut()
  setError(verdict.reason ?? 'Acces refuse par politique de securite.')
  return
}
window.location.href = '/dashboard'
```

**Politiques évaluées côté serveur :** P-001 (brute force), P-002 (pays inhabituel), P-004 (sessions excessives), P-007 (password expiré), P-008 (MFA obligatoire), P-010 (appareil inconnu), P-006 (compte inactif)

### 3.2 OAuth Callback (`app/auth/callback/route.ts`)

```typescript
// Après exchangeCodeForSession + tenant_id résolu
const policyContext = await buildPolicyContext(policyEvent, profile.tenant_id)
const policyResult  = evaluatePolicies(policyContext, { stopOnFirstDeny: true })

if (policyResult.denyDecision) {
  await supabase.auth.signOut()
  return NextResponse.redirect(`${origin}/login?error=policy_denied&reason=...`)
}
```

**Avantage :** 100% serveur-side — aucun appel client-side requis pour le flux OAuth.

### 3.3 Token Refresh (`middleware.ts`)

Détection via flag `tokenWasRefreshed` dans le callback `setAll()`. Logging `TOKEN_REFRESH` fire-and-forget via `fetch('/api/auth/log')`. Fournit les données pour P-005 (ABNORMAL_REFRESH).

**Note :** L'évaluation P-005 n'est pas déclenchée à chaque refresh (trop coûteux) — le Policy Engine évalue P-005 lors du prochain `LOGIN_SUCCESS` via le compteur `tokenRefreshesLast1h` dans le contexte.

### 3.4 Logout (4 composants)

```typescript
logAuthClient({ event_type: 'LOGOUT' })
await supabase.auth.signOut()
```

Pattern uniforme appliqué avec `keepalive: true` pour garantir que le log est envoyé avant la navigation.

## 4. Fonction SQL `fn_policy_context_counters`

```sql
fn_policy_context_counters(p_user_id UUID)
RETURNS TABLE (
  failed_15m, failed_1h, refresh_1h, mfa_1h,
  active_sessions_4h, last_password_reset, last_login_success
)
LANGUAGE sql STABLE SECURITY DEFINER
```

**Performance :** 1 seule requête SQL au lieu de 7 requêtes séparées. Fenêtre temporelle : 30 jours. Toutes les agrégations calculées en 1 pass avec `COUNT() FILTER (WHERE ...)`.
